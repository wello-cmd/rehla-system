# English and Arabic interface

The language button is available on sign-in, the navigation sidebar and public driver manifests. English is the default. The browser saves the choice as `rehla-language`; the document language and direction are applied before paint. Switching languages re-renders the existing React tree without resetting page, filter or form state.

`frontend/src/i18n/ar.js` holds Arabic interface copy keyed by English source text. `translate(key, values)` supports named interpolation, Arabic plural forms and an unchanged fallback for unknown text. `useLanguage` subscribes the application to language changes. Add translations only at presentation boundaries: option values, roles, status codes, API fields, identifiers and customer/product data must retain their original values. React escapes interpolated strings.

Arabic uses RTL document flow, logical spacing, a right-hand sidebar and drawer, mirrored navigation arrows, and isolated LTR fields for email, telephone, identifiers and numeric entry. Shared display formatters use Egyptian Arabic dates/currency while preserving numerical precision. Financial calculations and accounting definitions are unchanged.

Existing downloaded PDFs and CSV schemas retain English. The browser-generated financial PDF explicitly formats amounts in English because its font does not support Arabic. Unknown messages returned by external providers may remain in English. AI-generated answers and business records are not automatically translated.

Verification: 44 frontend tests, 106 backend tests, lint/build; browser DOM checks of Arabic sign-in/dashboard/delivery, persisted form content and stable delivery filter values across language changes. IAB screenshot capture failed and viewport override did not take effect, so mobile visual verification remains outstanding. Temporary read-only preview fixtures were removed before release.
